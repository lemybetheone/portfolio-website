Formula 1 analytics pipeline

Every Formula 1 season since 1950, pulled from a rate-limited public API, landed immutably in S3, loaded into Postgres, and modelled into a tested Kimball star schema with dbt. Orchestrated nightly by Airflow, served through Metabase.

01 — the pipeline

The API is rate limited to 500 requests an hour, so the landing zone is immutable: raw responses go to S3 once and are never re-fetched. Everything downstream can be rebuilt from that copy without spending the budget again.

02 — the model

Two fact tables at different grains, sharing conformed dimensions. Sprint results are a separate fact rather than a session_type column, because a fact whose grain needs a filter to be correct is a reliable source of wrong numbers.

03 — the test that earned its keep

One dbt test derives each championship total from the facts and compares it against the official standings. A row count would have passed. This did not.

tests/assert_championship_totals_match.sql
WITH derived AS (
  SELECT season, driver_key, SUM(points) AS derived_points
  FROM   fct_all_points          -- race + sprint
  GROUP BY 1, 2
)
SELECT s.season, s.official_points, d.derived_points
FROM   stg_official_standings s
JOIN   derived d USING (season, driver_key)
WHERE  s.official_points <> d.derived_points;
FAIL 1 row returned, expected 0
seasonofficialderiveddelta
2024437399−38

Sprint points were missing entirely. The fix was a second fact table and a union at the points layer — but the test is the part worth keeping, because it is the reason anyone knew.
